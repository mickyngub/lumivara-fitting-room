Wings attach to the sprite frame centre

drawWings positions both wings from this.sprite.x, and the player sprite uses origin x = 0.5, so wings attach to the centre of each 64–80 px frame. In several job and outfit atlases the body is drawn off-centre in its frame (a weapon fills one side), so the wings land beside the torso. The worst visible case is Crimson Swordsman facing south: the wings sit 5.5 game pixels left of his torso.

Torso offset from the wing anchor

Game pixels, idle frame 0. Positive means the body sits right of the anchor, so the wings look shifted left.

How it was measured

From each live atlas (/jobs/<look>/player.png and /novice-v6/, client main-C4qHILk_.js, 2026-10-03), take frame idle/<dir>/0, find the opaque pixels in the torso band (rows baseline − 26 to baseline − 16), and subtract half the frame width from the band's centre. Wing placement was confirmed by running the client's own setWings/drawWings in Phaser 3.90.

Ways to fix it

  1. Recentre the body in each frame when packing the atlases, so the frame centre is the torso. This also centres the shadow under the feet.
  2. Keep the art and add a per-texture, per-direction x offset to the wing anchor (u in drawWings), using the values above.
  3. Compute that offset at load time from each frame's torso band, the same measurement as this table, so new outfits stay aligned without a hand-kept list.
